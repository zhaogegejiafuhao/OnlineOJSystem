# CodeVertex 需求文档

## 1. 引言

### 1.1 文档目的

本文档详细描述了 CodeVertex 在线编程评测平台的功能需求、非功能需求、用户角色、业务流程等内容，为项目开发、测试、验收提供依据。

### 1.2 术语定义

| 术语 | 说明 |
|------|------|
| OJ | Online Judge，在线评测系统 |
| AC | Accepted，提交通过 |
| WA | Wrong Answer，答案错误 |
| TLE | Time Limit Exceeded，超时 |
| MLE | Memory Limit Exceeded，内存超限 |
| RE | Runtime Error，运行时错误 |
| CE | Compile Error，编译错误 |
| 评测机 | 负责编译和运行用户代码的服务 |
| 测试用例 | 用于验证程序正确性的输入输出数据 |

### 1.3 参考文档

- 项目计划文档
- 数据库设计文档
- API 接口文档

## 2. 用户角色

### 2.1 游客

**权限范围**：
- 浏览公开题目列表
- 查看比赛列表（公开比赛）
- 浏览论坛文章
- 查看排行榜
- 注册账号

**限制**：
- 无法提交代码
- 无法参加比赛
- 无法发表评论
- 无法查看题解

### 2.2 普通用户

**权限范围**：
- 游客所有权限
- 登录/登出
- 提交代码进行评测
- 查看自己的提交记录
- 参加公开比赛
- 发表论坛文章和评论
- 创建和加入队伍
- 管理个人信息
- 查看题解（达到条件）
- 使用错题本功能
- 使用 AI 辅助功能

### 2.3 教师用户

**权限范围**：
- 普通用户所有权限
- 创建和管理比赛
- 管理题目（审核）
- 管理用户
- 查看系统数据统计
- 发布公告

### 2.4 管理员

**权限范围**：
- 教师用户所有权限
- 系统配置管理
- 用户管理（包括封禁）
- 题目管理（完整权限）
- 比赛管理（完整权限）
- 数据备份与恢复
- 系统监控与告警
- 日志查看与分析

## 3. 功能需求

### 3.1 用户管理模块

#### 3.1.1 用户注册

**功能描述**：用户通过填写用户名、密码、邮箱等信息注册账号。

**输入**：
- 用户名（必填，3-30字符，唯一）
- 密码（必填，6-60字符）
- 确认密码（必填，与密码一致）
- 邮箱（必填，格式验证）
- 昵称（可选）

**输出**：
- 注册成功：跳转登录页
- 注册失败：显示错误信息

**业务规则**：
- 用户名不能包含特殊字符
- 密码需要加密存储（BCrypt）
- 邮箱需要唯一
- 注册成功后自动登录

#### 3.1.2 用户登录

**功能描述**：用户通过用户名/邮箱和密码登录系统。

**输入**：
- 用户名/邮箱
- 密码

**输出**：
- 登录成功：跳转首页，保存会话
- 登录失败：显示错误信息

**业务规则**：
- 支持用户名或邮箱登录
- 密码错误次数限制（5次锁定15分钟）
- 会话超时时间：350分钟
- 记住登录状态（可选）

#### 3.1.3 个人信息管理

**功能描述**：用户查看和修改个人信息。

**可修改信息**：
- 昵称
- 邮箱
- 个人简介
- 头像
- 密码（需验证旧密码）

**不可修改信息**：
- 用户名
- 注册时间
- 用户ID

#### 3.1.4 用户排行榜

**功能描述**：展示用户的排名情况。

**排名规则**：
- 按通过题目数降序
- 相同按提交时间升序
- 显示积分、通过数、提交数

**展示内容**：
- 排名
- 用户名
- 头像
- 积分
- 通过题目数
- 提交数

### 3.2 题目管理模块

#### 3.2.1 题目列表

**功能描述**：展示所有公开题目，支持筛选和搜索。

**筛选条件**：
- 题目难度
- 题目标签
- 题目来源
- 通过状态（已通过/未通过）

**排序方式**：
- 按题目ID
- 按通过数
- 按提交数
- 按难度

**展示信息**：
- 题目ID
- 题目标题
- 难度
- 通过数/提交数
- 通过率
- 标签

#### 3.2.2 题目详情

**功能描述**：展示题目的详细信息。

**展示内容**：
- 题目标题
- 题目描述
- 输入格式
- 输出格式
- 样例输入
- 样例输出
- 提示
- 来源
- 时间限制
- 内存限制
- 提交记录
- 题解（达到条件）

#### 3.2.3 代码提交

**功能描述**：用户提交代码进行在线评测。

**支持语言**：
- C
- C++
- Java
- Python 2
- Python 3
- Go

**提交内容**：
- 选择编程语言
- 编写/粘贴代码
- 提交评测

**评测反馈**：
- 实时状态更新
- 各测试用例结果
- 总用时
- 总内存
- 错误信息（如有）

#### 3.2.4 提交记录

**功能描述**：查看代码提交历史记录。

**筛选条件**：
- 用户（自己/全部）
- 题目
- 结果
- 语言
- 时间范围

**展示信息**：
- 提交ID
- 用户名
- 题目
- 结果
- 用时
- 内存
- 语言
- 代码长度
- 提交时间

**操作**：
- 查看代码（分享的代码）
- 再次提交

#### 3.2.5 题解管理

**功能描述**：发布和查看题解。

**发布题解**：
- 需要达到一定积分
- 需要通过该题目
- 支持 Markdown 格式

**查看题解**：
- 需要达到一定积分
- 或通过该题目

**题解评论**：
- 支持评论和回复
- 支持点赞

#### 3.2.6 题目标签

**功能描述**：管理题目的分类标签。

**标签类型**：
- 算法标签（动态规划、贪心等）
- 数据结构标签（数组、链表等）
- 难度标签（入门、中等、困难）
- 来源标签（比赛、课程等）

**标签操作**：
- 管理员可创建、编辑、删除标签
- 用户可通过标签筛选题目
- 标签可关联多个题目

### 3.3 竞赛管理模块

#### 3.3.1 竞赛列表

**功能描述**：展示所有竞赛。

**竞赛类型**：
- 公开竞赛（所有人可见）
- 私有竞赛（需密码或邀请）

**展示信息**：
- 竞赛标题
- 开始时间
- 结束时间
- 竞赛状态（未开始/进行中/已结束）
- 参赛人数
- 创建者

#### 3.3.2 竞赛详情

**功能描述**：展示竞赛的详细信息。

**展示内容**：
- 竞赛标题
- 竞赛描述
- 开始时间
- 结束时间
- 竞赛规则
- 题目列表
- 实时排名
- 公告

#### 3.3.3 竞赛参加

**功能描述**：用户参加竞赛。

**参加方式**：
- 公开竞赛：直接参加
- 私有竞赛：输入密码或邀请码

**竞赛规则**：
- 竞赛期间只能查看竞赛题目
- 提交计入竞赛排名
- 支持封榜功能

#### 3.3.4 竞赛排名

**功能描述**：实时展示竞赛排名。

**排名规则**：
- ACM 模式：按通过题数降序，罚时升序
- OI 模式：按得分降序

**展示内容**：
- 排名
- 用户名
- 通过题数
- 罚时/得分
- 各题状态

**封榜功能**：
- 竞赛后期可封榜
- 封榜后排名不再更新
- 结束后统一显示最终排名

#### 3.3.5 竞赛管理

**功能描述**：创建和管理竞赛。

**创建竞赛**：
- 设置竞赛标题和描述
- 设置开始和结束时间
- 设置竞赛类型（公开/私有）
- 选择竞赛题目
- 设置竞赛规则

**管理竞赛**：
- 编辑竞赛信息
- 添加/删除题目
- 发布公告
- 查看参赛情况
- 重置竞赛

### 3.4 论坛社区模块

#### 3.4.1 文章列表

**功能描述**：展示论坛文章。

**分类**：

**展示内容**：
- 文章标题

- 文章内容（Markdown）

**操作**：
- 发表评论

#### 3.4.3 发表文章

**功能描述**：管理文章评论。

**评论内容**：

### 3.5 队伍管理模块

## 4. 非功能需求

### 4.1 性能需求

| 指标 | 要求 |
|------|------|
| 系统可用性 | ≥ 99.9% |
| 页面加载时间 | ≤ 2秒 |
| API 响应时间 | ≤ 500ms |
| 评测响应时间 | ≤ 5秒 |
| 并发用户数 | ≥ 1000 |
| 日提交量 | ≥ 10000 |

### 4.2 安全需求

- 用户密码必须加密存储（BCrypt）
- 防止 SQL 注入攻击
- 防止 XSS 跨站脚本攻击
- 防止 CSRF 跨站请求伪造
- 敏感操作需要二次验证
- 日志记录所有敏感操作
- 定期安全审计
- 数据传输使用 HTTPS

### 4.3 可用性需求

- 界面简洁美观，易于使用
- 响应式设计，支持多种设备
- 提供详细的使用帮助
- 支持多种浏览器
- 提供快捷键操作

### 4.4 可维护性需求

- 代码结构清晰，注释完善
- 遵循编码规范
- 模块化设计，低耦合高内聚
- 完善的日志记录
- 易于扩展和升级

### 4.5 兼容性需求

- 支持主流浏览器（Chrome、Firefox、Safari、Edge）
- 支持移动端访问
- 支持多种分辨率
- 前后端分离，易于适配

## 5. 数据需求

### 5.1 数据实体

**核心实体**：
- 用户（User）
- 题目（Problem）
- 提交记录（Solution）
- 竞赛（Contest）
- 文章（Article）
- 评论（Comment）
- 队伍（Team）

**关联实体**：
- 用户配置（UserProfile）
- 题目标签（Tag）
- 题目标签关联（ProblemTags）
- 竞赛题目（ContestProblem）
- 文章评论关联（ArticleComment）
- 队员（Teammate）
- 队伍申请（TeamApply）
- 错误记录（ErrorRecord）
- 错误分类（ErrorCategory）

### 5.2 数据量预估

| 实体 | 初期 | 中期 | 长期 |
|------|------|------|------|
| 用户 | 1000 | 10000 | 100000 |
| 题目 | 100 | 1000 | 10000 |
| 提交记录 | 10000 | 100000 | 1000000 |
| 竞赛 | 10 | 100 | 1000 |
| 文章 | 100 | 1000 | 10000 |

### 5.3 数据备份

- 数据库每日增量备份
- 数据库每周全量备份
- 备份文件保留 30 天
- 重要数据异地备份

## 6. 接口需求

### 6.1 用户接口

- POST /api/user/register - 用户注册
- POST /api/user/login - 用户登录
- POST /api/user/logout - 用户登出
- GET /api/user/profile - 获取用户信息
- PUT /api/user/profile - 更新用户信息
- GET /api/user/ranklist - 获取排行榜

### 6.2 题目接口

- GET /api/problem/list - 获取题目列表
- GET /api/problem/{id} - 获取题目详情
- POST /api/problem/submit - 提交代码
- GET /api/problem/status - 获取提交记录
- GET /api/problem/solution/{id} - 获取提交详情

### 6.3 竞赛接口

- GET /api/contest/list - 获取竞赛列表
- GET /api/contest/{id} - 获取竞赛详情
- POST /api/contest/{id}/join - 参加竞赛
- GET /api/contest/{id}/rank - 获取竞赛排名

### 6.4 论坛接口

- GET /api/article/list - 获取文章列表
- GET /api/article/{id} - 获取文章详情
- POST /api/article - 发表文章
- POST /api/article/{id}/comment - 发表评论
